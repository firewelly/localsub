## 按环节排错

### 0. 环境检查阶段

#### 0.1 驱动与 Vulkan 验证

**问题**：不确定显卡驱动是否支持 Vulkan。

**排查步骤**：

1. **检查驱动版本**

   ```powershell
   # 方法一：任务管理器 → 性能 → GPU
   # 方法二：设备管理器 → 显示适配器 → 右键属性
   ```

2. **检查 Vulkan 支持**

   - 下载安装 [Vulkan SDK](https://vulkan.lunarg.com/sdk/home)（可选）
   - 运行 `vulkaninfo` 命令（Vulkan SDK 自带）

   ```powershell
   vulkaninfo
   # 应列出 Intel Arc A770 及支持的 Vulkan 版本
   ```

3. **查看 whisper 日志**

   ```powershell
   .\tools\windows\whisper-cli.exe -m .\models\whisper\ggml-large-v3.bin -f .\work\test.wav -l ja --vad -vm .\models\whisper\ggml-silero-v5.1.2.bin -osrt 2>&1 | Tee-Object -FilePath .\logs\whisper-test.log
   Select-String -Path .\logs\whisper-test.log -Pattern "Vulkan|ggml_vulkan"
   ```

   预期看到：
   - `ggml_vulkan: Found N Vulkan devices`
   - `ggml_vulkan: 0 = Intel(R) Arc(TM) A770 Graphics`

[来源:推断,需实机验证] 关键字取自 ggml Vulkan 后端通用日志惯例。

**修复方案**：

- 更新 Intel Arc 驱动到最新版：[Intel 驱动下载页](https://www.intel.com/content/www/us/en/download-center/home.html)
- 若仍不支持 Vulkan，尝试 OpenVINO 后端（见路线 B）

#### 0.2 SYCL 后端 DLL 缺失

**问题**：使用 SYCL 版 llama-server 时报 DLL 缺失。

**典型错误**：

```
无法启动此程序，因为计算机中丢失 sycl7.dll
```

**排查步骤**：

1. 查看具体缺失的 DLL 名称（如 `sycl7.dll`、`ur_loader.dll` 等）
2. 确认是否安装了 Intel oneAPI runtime

**修复方案**：

- **方案一**：安装 Intel oneAPI Base Toolkit（选择 Runtime only）
  - 下载：[Intel oneAPI Base Toolkit](https://www.intel.com/content/www/us/en/developer/tools/oneapi/base-toolkit-download.html)
- **方案二**：改用 Vulkan 版（路线 A），无需额外 runtime

[来源:推断,需实机验证] SYCL 依赖 oneAPI runtime，具体 DLL 需看报错。

---

#### 0.3 显存不足

**问题**：模型加载失败或运行时报 OOM（Out of Memory）。

**排查步骤**：

1. **检查显存占用**

   ```powershell
   # 方法一：任务管理器 → 性能 → GPU → Dedicated GPU memory
   # 方法二：GPU-Z 工具
   ```

2. **检查模型大小**

   - Whisper large-v3：≈3.1GB
   - Sakura 7B Q6K：≈6.3GB
   - 14B 模型：≈9GB+

3. **检查并发运行**

   - 是否同时运行 whisper 和 llama-server？

**修复方案**：

- **方案一**：串行运行（先听写、后翻译）
- **方案二**：减小翻译模型（用 Q4_K_M 而非 Q6K）
- **方案三**：降低 GPU offload 层数

   ```powershell
   # 原命令
   .\tools\windows\llama-server.exe -m ... -ngl 99
   # 改为（只 offload 部分层）
   .\tools\windows\llama-server.exe -m ... -ngl 30
   ```

- **方案四**：减小上下文长度

   ```powershell
   # 原命令
   .\tools\windows\llama-server.exe -m ... -c 4096
   # 改为
   .\tools\windows\llama-server.exe -m ... -c 2048
   ```

[来源:推断,需实机验证] 基于 GGUF 文件大小估算显存，实机以任务管理器为准。

#### 0.4 模型文件校验

**问题**：怀疑模型文件损坏或下载不完整。

**排查步骤**：

```powershell
# 计算文件的 SHA256
$hash = Get-FileHash .\models\whisper\ggml-large-v3.bin -Algorithm SHA256
$hash.Hash

# 与 CHECKSUMS.sha256 比对
Get-Content .\models\CHECKSUMS.sha256 | Select-String "ggml-large-v3.bin"
```

**修复方案**：

- 若校验不匹配，重新下载模型（见 `models/MANIFEST.md` 中的下载链接）

[来源:已核实] 模型文件清单与哈希见 `models/MANIFEST.md`。

### 1. 听写阶段

#### 1.1 Whisper 日语幻觉/重复句

**问题**：输出的 SRT 中出现大量重复句或与音频无关的内容（幻觉）。

**原因**：
- 未启用 `-sns`（suppress non-speech tokens）参数
- VAD 模型未正确加载
- 音频质量差（背景噪音大）

**排查步骤**：

1. 检查命令是否包含 `-sns` 参数：

   ```powershell
   # 正确命令（包含 -sns）
   .\tools\windows\whisper-cli.exe ... -sns ...
   ```

2. 检查 VAD 模型是否加载：

   ```powershell
   # 查日志
   Select-String -Path .\logs\whisper-*.log -Pattern "VAD|silero"
   ```

**修复方案**：

- 确保命令包含 `-sns` 参数
- 确保使用 `--vad -vm .\models\whisper\ggml-silero-v5.1.2.bin`
- 若音频质量差，尝试先用音频处理工具降噪

[来源:已核实] `-sns`、`--vad`、`-vm` 参数已在 jerryshell README 中核实。

---

#### 1.2 时间轴漂移/不对齐

**问题**：SRT 时间轴与视频音频不匹配。

**原因**：
- VAD 模型版本不匹配
- 音频采样率不正确
- whisper.cpp 构建版本与 VAD 模型不兼容

**排查步骤**：

1. 检查音频是否为 16kHz 单声道 PCM WAV：

   ```powershell
   .\tools\windows\ffmpeg.exe -i .\work\test.wav
   # 确认 Stream #0:0: Audio: pcm_s16le, 16000 Hz, mono
   ```

2. 检查 VAD 模型版本：

   ```powershell
   # 当前使用的 VAD 模型
   Get-Item .\models\whisper\ggml-silero-v5.1.2.bin
   # jerryshell 示例用的是 v5.1.2
   # whisper.cpp 1.9.5 官方示例已换成 v6.2.0
   ```

**修复方案**：

- 确保 ffmpeg 抽音频参数正确：`-ar 16000 -ac 1 -c:a pcm_s16le`
- 尝试不同 VAD 模型版本（v5.1.2 vs v6.2.0）

[来源:已核实] whisper.cpp 只接受 16-bit WAV；VAD 模型版本配套问题见 `docs/research/01-arc-toolchain.md` §3.2。

---

#### 1.3 未启用 GPU 加速

**问题**：听写速度极慢，怀疑回落到 CPU。

**排查步骤**：

1. 查看日志是否有 Vulkan 关键字：

   ```powershell
   Select-String -Path .\logs\whisper-*.log -Pattern "Vulkan|CPU"
   ```

   - 若只有 `CPU backend`，说明未启用 Vulkan
   - 若有 `ggml_vulkan: Found ...`，说明已启用

2. 任务管理器看 GPU 占用：

   - 听写期间，GPU 应有明显占用（>50%）
   - 若 GPU 占用为 0，说明未用 GPU

**修复方案**：

- 更新 Intel Arc 驱动
- 确认使用的是 Vulkan 版 whisper-cli（jerryshell 包）
- 重新下载 Vulkan 版构建

[来源:推断,需实机验证] 日志关键字取自 ggml 通用惯例。

### 2. 翻译阶段

#### 2.1 llama-server 端口占用

**问题**：启动 llama-server 时报端口被占用。

**错误信息**：

```
bind: Address already in use
```

**排查步骤**：

```powershell
# 查看端口占用
netstat -ano | findstr :8080
# 输出示例：
# TCP    127.0.0.1:8080    0.0.0.0:0    LISTENING    12345

# 查看占用进程
tasklist | findstr 12345
```

**修复方案**：

- **方案一**：杀掉占用进程

   ```powershell
   taskkill /PID 12345 /F
   ```

- **方案二**：改用其他端口

   ```powershell
   .\tools\windows\llama-server.exe --port 8081 ...
   ```

   翻译脚本也需要同步修改：

   ```powershell
   .\scripts\windows\02-translate.ps1 -ServerUrl http://127.0.0.1:8081
   ```

---

#### 2.2 llama-server 健康检查超时

**问题**：脚本启动 llama-server 后等待健康检查超时。

**原因**：
- 模型加载慢（大模型 + 首次加载）
- 显存不足导致加载失败

**排查步骤**：

1. 手动启动 llama-server 看日志：

   ```powershell
   .\tools\windows\llama-server.exe -m .\models\translation\Sakura-Galtransl-7B-v3.7.gguf --host 127.0.0.1 --port 8080 -ngl 99 -c 4096
   ```

   观察：
   - 模型是否成功加载（看 `llama_model_load` 日志）
   - 显存是否足够（任务管理器）

2. 测试 API 是否响应：

   ```powershell
   Invoke-RestMethod -Uri "http://127.0.0.1:8080/health"
   ```

**修复方案**：

- 增加等待时间（脚本参数）
- 减小模型（Q4_K_M）
- 降低 `-ngl` 或 `-c`

---

#### 2.3 翻译输出中英混杂/漏译

**问题**：翻译结果不理想，出现中英混杂、漏译或译文过长。

**原因**：
- prompt 不当
- 采样参数不合适
- 模型版本问题

**排查步骤**：

1. 检查 system prompt：

   ```powershell
   # 应使用 Sakura 官方 prompt
   $sys = "你是一个轻小说翻译模型，可以流畅通顺地以日本轻小说的风格将日文翻译成简体中文，并联系上下文正确使用人称代词，不擅自添加原文中没有的代词。"
   ```

[来源:已核实] SakuraLLM README 推荐的 prompt 模板。

2. 检查解码参数：

   ```powershell
   # Sakura 官方推荐参数
   $body = @{
     model = "sakura"
     temperature = 0.1
     top_p = 0.3
     max_tokens = 512
     ...
   }
   ```

[来源:已核实] SakuraLLM README 推荐参数：temperature 0.1 / top_p 0.3 / repetition_penalty 1 / max_tokens 512。

**修复方案**：

- 使用官方推荐的 prompt 模板
- 使用推荐的解码参数
- 若出现重复，尝试加 `frequency_penalty = 0.1~0.2`

[来源:已核实] 频率惩罚参数来自 SakuraLLM README。

---

#### 2.4 翻译 API 请求失败

**问题**：调用翻译 API 时返回错误或超时。

**排查步骤**：

1. 测试 llama-server 是否运行：

   ```powershell
   Invoke-RestMethod -Uri "http://127.0.0.1:8080/v1/models"
   ```

2. 测试简单翻译请求：

   ```powershell
   $body = @{
     model = "sakura"
     messages = @(
       @{ role = "system"; content = "你是翻译助手" },
       @{ role = "user"; content = "翻译：こんにちは" }
     )
   } | ConvertTo-Json -Depth 6

   Invoke-RestMethod -Uri "http://127.0.0.1:8080/v1/chat/completions" -Method Post -ContentType "application/json; charset=utf-8" -Body $body
   ```

**修复方案**：

- 检查 llama-server 是否正常启动
- 检查端口是否正确
- 检查请求体格式（JSON）
- 检查网络/防火墙设置

### 3. 合并/质检阶段

#### 3.1 SRT 编码问题（UTF-8 BOM）

**问题**：播放器显示乱码或无法加载 SRT。

**原因**：SRT 文件编码不一致（UTF-8 vs UTF-8 BOM）。

**排查步骤**：

```powershell
# 用文本编辑器（如 Notepad++）打开 SRT
# 查看右下角编码信息
```

**修复方案**：

- 统一使用 UTF-8（无 BOM）或 UTF-8 with BOM
- 修改脚本输出编码（见 `config/pipeline.json`）

---

#### 3.2 双语合并失败

**问题**：`bilingual.srt` 生成失败或条数不对。

**排查步骤**：

1. 检查 `ja.srt` 和 `zh.srt` 是否存在：

   ```powershell
   Test-Path .\output\test\ja.srt
   Test-Path .\output\test\zh.srt
   ```

2. 检查条数是否一致：

   ```powershell
   # 统计条数
   (Get-Content .\output\test\ja.srt | Select-String "^\d+$").Count
   (Get-Content .\output\test\zh.srt | Select-String "^\d+$").Count
   ```

**修复方案**：

- 若条数不一致，检查翻译日志是否有漏译
- 手动对齐时间戳

### 4. 其他常见问题

#### 4.1 PowerShell 执行策略禁止

**问题**：无法运行 `.ps1` 脚本，提示执行策略限制。

**错误信息**：

```
无法加载文件，因为在此系统上禁止运行脚本
```

**排查步骤**：

```powershell
Get-ExecutionPolicy
# 可能返回 Restricted 或 RemoteSigned
```

**修复方案**：

```powershell
# 以管理员身份运行 PowerShell
Set-ExecutionPolicy RemoteSigned
# 或临时绕过
PowerShell -ExecutionPolicy Bypass -File .\scripts\windows\run-all.ps1
```

---

#### 4.2 路径问题（中文/空格/盘符变化）

**问题**：命令报路径错误。

**原因**：
- 路径包含中文或空格未加引号
- 硬盘插到不同盘符导致绝对路径失效

**排查步骤**：

1. 检查路径是否包含中文或空格：

   ```powershell
   # 错误示例（路径有空格）
   .\tools\windows\ffmpeg.exe -i "C:\Users\My User\test.mp4"
   # 正确写法（加引号）
   .\tools\windows\ffmpeg.exe -i "C:\Users\My User\test.mp4"
   ```

2. 检查当前盘符：

   ```powershell
   Get-Location
   # 输出：D:\transub 或 E:\transub 等
   ```

**修复方案**：

- **所有路径加引号**
- **使用相对路径**，不硬编码盘符

---

#### 4.3 babelscribe 首次运行联网下载失败

**问题**：babelscribe 首次运行时无法下载 Vulkan 版 whisper-cli 或模型。

**原因**：
- 网络问题（需翻墙访问 GitHub/HuggingFace）
- 离线环境

**修复方案**：

- **方案一**：配置代理

   ```powershell
   $env:HTTP_PROXY = "http://127.0.0.1:1080"
   $env:HTTPS_PROXY = "http://127.0.0.1:1080"
   babelscribe .\input\test.mp4 -l ja -f srt
   ```

- **方案二**：离线使用预下载的模型

   ```powershell
   # 指定自有的 whisper-cli
   babelscribe .\input\test.mp4 -l ja -f srt --bin .\tools\windows\whisper-cli.exe
   # 指定模型目录
   $env:BABELSCRIBE_MODELS = ".\models\whisper"
   ```

[来源:已核实] babelscribe README 支持 `--bin` 和 `BABELSCRIBE_MODELS` 环境变量。

| 错误代码 | 含义 | 常见场景 | 解决方案 |
|---------|------|---------|---------|
| `0x80070002` | 文件未找到 | 工具/模型路径错误 | 检查文件是否存在 |

| `EXIT CODE 1` | 脚本失败 | 通用错误 | 查看日志定位原因 |
